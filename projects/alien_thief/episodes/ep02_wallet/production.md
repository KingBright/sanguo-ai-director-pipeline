# 《这钱眼熟》制作记录

状态：完整候选片已生成，完成下述技术与抽帧检查；用户尚未验收。故事和对白见 `story.md`，实际音频条件与镜头提示见 `performance.json`。

`audio/` 是本片新生成的原创合成角色对白，沿用 V3 的固定卡托/西木参考声线，未变速。离场文件是明确的无对白条件，不能作为“有声台词”通过质检。背景音乐使用已生成的 Flow Music《Alien Alley Lottery》，不包含参考 B 站视频的音轨。

在已安装并验证的 MiniMax H3/DiffSynth GPU 环境中，从仓库根目录运行：

```sh
python scripts/h3_performance.py projects/alien_thief/episodes/ep02_wallet/performance.json --model-root /path/to/MiniMax-H3 --output /path/to/new-take
```

每次重做必须使用新目录；支持 `--shot intro` 选择独立镜头。`keyframe_from` 指向本次选择中先生成的镜头；单独续拍时应把已人工检查过的末帧作为显式 `keyframe` 输入。生成后需要检查脸、手、道具、说话者和反应，不把未检查的末帧继续传播。

结尾先行试验使用同一构图的基准图，分为收回钱包/控制人物与离场两个动作镜头。实际剪辑需检查与前镜的空间和动作连续性，不能凭提示文本认定衔接成立。最终片的选段和验收记录须另行保存。

## 实战中已经确认的问题与修复

- 原先的局部贴脸、按音量拉嘴、为了镜头长度加速对白，不再进入出镜对白成片流程。完整台词先表演，再由音频条件动画生成对应画面。
- 识破镜头第一版、解释镜头第一版出现模型生成字幕，均淘汰。识破镜头改成只在音轨表达对白，并明确空手摸口袋、另一手持铐。解释镜头启用实际执行的负面引导后重新检查，未再见字幕乱入。
- 离场第一版出现倒着走，淘汰；提示明确朝向、移动方向、接触关系与钱包归属。
- 第一次完整剪辑在17.583秒出现姿态/构图跳变。原因是结尾试拍从初始基准图开始，而正片已经推进到伸手索要钱包。技术检查通过并不能证明镜头衔接成立；正式结尾改从解释镜头的实际末帧续拍。
- 远端 FFmpeg 9 已移除 `-vsync`。逐帧校验改用 `-fps_mode passthrough`，本地9项相关测试通过；真实远端合成也已完成620帧和原生PCM一致性检查。

## 验收分层

故事要检查的是“行贿为何失败、钱包是否归还、人物是否被带走”；表演要检查的是“谁在说、谁在听、什么时候意识到说漏嘴、嘴部是否跟随话段与停顿”。技术层单独检查帧来源、同区间剪辑、音频未变速、闪帧、声压及导出。用户是否认可单独记录，不能由上述检查自动赋值。

第一份完整剪辑的数据为25.833秒、620帧、SSIM 0.987600、综合响度-20.68 LUFS、真峰值-4.18 dBTP，孤立整帧闪烁候选为0；该版仍因接缝问题被淘汰。这些数字仅说明对应技术项，不代表作品已经合格。
