# 外星小偷：问题定位与故事驱动验证

## 原片问题的证据

检查对象为 DeepSeek harness 会话 `session-071578ca-53d5-4aec-99b8-1525b05ba68f` 交付的 71.64 秒《烂柯星刮刮乐大劫案》，以及 CUBEX 上保留的 Veo 原片、对白和后期脚本。

| 问题 | 已确认的原因 | 修复方向 |
| --- | --- | --- |
| 矩形撕裂、闪入其他时刻的画面 | `process_v2_master_airlock.py` 在静音和字间停顿时，把 x=11%–89%、y=34%–79% 的区域替换成另一时刻的整块画面；同时按音量向上扭动局部像素。同一时刻的原始 Veo 片与后期片对照能看出后期新增的断层。 | 保留完整原帧；不做局部冻结、贴帧或音量驱动像素嘴形。 |
| 赶台词、声线变形 | `assemble_v2_airlock.py` 用 `signal.resample` 把每轮对白压成 2.15 秒。24 段台词平均约 10.64 汉字/秒，范围 7.91–12.56。直接改采样长度同时改变速度和音高。 | 先做人物表演，再据实际声音剪辑；不足时补镜，不加速或截词。 |
| 声音和表演不稳定 | 旧流程逐句重新 VoiceDesign，随后多次改时长；没有把稳定身份与当句意图分开。 | 原创合成音色固定为角色参考；台词、重音、停顿、对象和情绪变化单独设计、试演。 |
| 自动评分与观感不符 | 旧报告 `passed=true`，总分 89.2、视觉分 100；其依据主要是运动量、音量相关性及对比度。后期还加入 600 Hz 正弦音迎合静音阈值。 | 离线质检只能诊断，不能批准成片；取消测试音和迎合指标的图像处理。 |

以上证明了后期造成的具体损伤，不能据此断言视频模型的所有输出都没有缺陷。模型的身份、动作、道具与口型仍要检查。

## 制片顺序

故事目标与因果 → 人物欲望及关系 → 场景行动和对白 → 角色声线及当句表演 → 完整试演 → 按实际声音安排说话者/听者/反应镜头 → 配乐与混音 → 技术和故事分别验收。

“约 30 秒”是体量预期，不是每镜等长、每句等字数的任务。西木的长篇狡辩、小黛惜字的事实提醒、卡托被打断的虚张声势共同组成同一个笑点。具体设计见 [《两块五的尊严》](../projects/alien_thief/episodes/ep01_lottery_heist/story_v3.md)。

## V3 技术结果（作品已被用户拒绝）

**2026-11-06 用户验收：拒绝。故事未完成、音画严重不同步、人物活人感不足。以下仅为技术记录，不是作品验收通过。** 后续方法见 [故事与表演制作方法](../.agents/skills/director-story/references/story-performance-method.md)。

- 样片《两块五的尊严》：26.542 秒、1280×720、24 fps，六段对白和结尾反应镜头。语音保持 1.0 倍速，各句约 2.7–4.0 汉字/秒；这个范围是表演结果，不是事先的字数配额。
- Qwen3 VoiceDesign 建立原创角色参考，Base 固定身份。卡托、女声小黛、鼻音西木分别表现不同的说话方式。当前 Base 没有独立情绪指令接口，`delivery` 是试演/选段标准，实际控制来自参考声与标点。
- Google Flow Music 实际生成并下载 `Alien Alley Lottery`（原曲约 104.9 秒）。对白下方自动压低音乐，报出罚款时进一步让位，结尾淡出；没有使用原参考片的音轨。
- Veo 本次生成的镜头作为画面素材。两次失败的提醒镜头使用同次制作中已成功生成、动作相符的反应素材；360p 候选未采用，开场改用原生 720p 建立镜头。保存实际来源，不把失败报告成成功。
- 素材含 BT.601/sRGB 与 BT.709 标记。先明确转换为 BT.709，再进行无损剪辑；637 帧与规范化后的来源逐帧一致。保留原始文件及每个片段的入出帧、来源哈希、色彩转换记录。
- 播放版为 H.264 High/AAC，约 13.8 MB；与无损母版的全片 SSIM 为 0.9941。最终混音约 -18.21 LUFS、真峰值 -4.79 dBTP。
- 12 项 Python 测试通过，包含不同色彩标准的跨镜头剪辑、音频混合、逐帧核对，以及“高诊断分不能自动批准成片”的回归；离线质检自测通过。

后配音尚未做逐音素口型同步。抽帧、切点、完整声轨和帧来源检查不能替代观众对表演和笑点的最终判断，不使用“百分之百同步/一致”的结论。

## 客户端使用

`director-speech`、`director-bgm`、`director-story` 为独立入口。`director-story` 已安装到本机和 Mac Studio 的 Codex/Antigravity/DeepSeek harness、CUBEX 的 Antigravity/DeepSeek harness，以及 HO5 的 Antigravity；两台 Mac 的 Codex 技能发现接口均显示启用。其他客户端通过新会话加载文件。

技能安装与模型/登录状态是两回事。本次真实语音在 CUBEX 的已有 GPU 环境生成，Flow Music 使用本机获授权的浏览器会话。RPi-400 离线，未安装；旧 Whatfor 连接记录未恢复。没有把凭据或大型模型复制到所有设备。
